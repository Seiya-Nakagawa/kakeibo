# GAS版停止・スプレッドシートアーカイブ化手順書

## 1. 概要

対応する Issue: [#32 GAS版の停止・スプレッドシートのアーカイブ化](https://github.com/Seiya-Nakagawa/kakeibo/issues/32)

新システム（Django + MySQL, OCI 本番環境）への移行完了後、旧 GAS 版を停止し、
現行スプレッドシートを参照専用のアーカイブとする。対応する要件は
[要件定義書 4.10.4](../../01.要件定義/要件定義書.md#410-データ移行機能) に定める。

- GAS のインストール型トリガーおよび Web アプリデプロイを停止・削除する
- スプレッドシートの編集権限を参照専用へ変更する

Google Apps Script プロジェクトのオーナーアカウントとスプレッドシートのオーナーアカウントが
異なるため、本手順はユーザー自身が該当アカウントで手動実施する。

GAS のメール取込トリガーは2026-09-06時点で既に停止済みであることを確認済み（3.1は実施完了）。
2026-09-18にデータ移行の最終確認として、本番DBの移行データ（361件・1,174,185円）が2026-09-06時点から
変更されていないこと、および直近2ヶ月（2026-08・2026-09）分がスプレッドシートの記録と完全一致することを
確認した。3.2・3.3（デプロイ削除・共有権限の参照専用化）はユーザー判断により実施を見送り、
スプレッドシートは現状のまま放置する方針とした。再度実施が必要になった場合は、
本手順の3.2・3.3をそのまま利用できる。

## 2. 前提条件

- Apps Script プロジェクト（スクリプト ID: `1ghoxTxId1xjThD7aJw6F2tff84CcSeLERKeUcMire2tMfpOfLFvWgRGy`）への
  編集権限を持つ Google アカウントでログイン済みであること（`clasp` の認可アカウントは
  `aibdlnew1.sn@gmail.com`）
- スプレッドシート（ファイル ID: `1luvgNYZpWmbj7TRzeCTtRJ95rp0W4Kwi2jVFSAFjvqc`）のオーナー権限を持つ
  Google アカウントでログイン済みであること
- 新システムでのメール取込・データ参照が問題なく稼働していることを確認済みであること

## 3. 手順

### 3.1. GAS トリガーの削除

1. ブラウザで Apps Script プロジェクトを開く。

   ```text
   https://script.google.com/d/1ghoxTxId1xjThD7aJw6F2tff84CcSeLERKeUcMire2tMfpOfLFvWgRGy/edit
   ```

2. 左側メニューの「トリガー」（時計アイコン）を開き、登録されているトリガーを確認する。
3. 登録されている各トリガーの右上メニューから「トリガーを削除」を選択し、すべて削除する。
4. 「トリガー」画面の一覧が空になっていることを確認する。

### 3.2. Web アプリデプロイの削除

1. Apps Script プロジェクトのエディタ画面右上「デプロイ」から「デプロイを管理」を開く。
2. 現在有効なデプロイ（デプロイ ID: `AKfycbxQiAEzRszEPxPyhS1eAjRhpWD01QF9p3lVDnZ3GEYL`）を選択する。
3. 鉛筆アイコン（編集）を開き、「ステータス」を「アーカイブ済み」に変更して保存する。
4. デプロイ済みの `/exec` URL に再度アクセスし、応答がなくなった（停止した）ことを確認する。

### 3.3. スプレッドシートの共有権限変更

1. ブラウザでスプレッドシートを開く。

   ```text
   https://docs.google.com/spreadsheets/d/1luvgNYZpWmbj7TRzeCTtRJ95rp0W4Kwi2jVFSAFjvqc/edit
   ```

2. 右上「共有」を開き、編集者として登録されているユーザー・サービスアカウントを確認する。
3. GAS の実行アカウント（`aibdlnew1.sn@gmail.com`）を含む編集者権限を「閲覧者」に変更する
   （オーナー自身の権限は変更しない）。
4. リンクを知っている全員に対する共有設定がある場合は、権限を「閲覧者」に変更する。
5. 変更後、GAS 実行アカウントなど編集者だったアカウントで開き直し、編集操作（セル入力等）が
   できないこと（閲覧のみ可能なこと）を確認する。

## 4. 完了後の確認

- 3.1 でトリガー一覧が空であること、3.2 で `/exec` URL が応答しないこと、3.3 で編集操作が
  できないことを、それぞれの手順内の確認項目で確かめる。
- Issue #32 は、3.1（トリガー停止）の完了とデータ移行の最終確認をもってクローズする。
  3.2・3.3 は将来必要になった場合に実施する。
