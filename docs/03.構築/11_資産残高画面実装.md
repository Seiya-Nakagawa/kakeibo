## 1. 概要

対応Issue: [#26](https://github.com/Seiya-Nakagawa/kakeibo/issues/26)

口座別残高・総資産と資産推移グラフの表示（画面6）、残高記録入力（画面7）を実装する。
対応する設計書: [基本設計書5.3.5節](../02.設計/基本設計書.md#535-資産残高6)

## 2. 前提条件

- [10_集計・ダッシュボード画面実装.md](10_集計・ダッシュボード画面実装.md) の完了により
  `aggregation.account_balances`等が利用可能であること

## 3. 手順

### 3.1. 残高記録入力フォームを追加する

`webapp/kakeibo/forms.py` に以下を追加する。

```python
class BalanceRecordForm(forms.ModelForm):
    """画面7 残高記録入力（基本設計書5.1.1節）。

    要件4.6.3（同一口座・同一基準日は上書き）に対応するため、呼び出し側
    （ビュー）は既存レコードがあればform_kwargsの`instance`にそれを渡す。
    """

    class Meta:
        model = BalanceRecord
        fields = ("account", "recorded_date", "balance")
        widgets = {
            "recorded_date": forms.DateInput(attrs={"type": "date"}),
        }
```

- 要件4.6.3「同一口座・同一基準日の記録は1件に限定し、再登録時は上書きする」の実現方式として、
  `BalanceRecord`モデルの`UniqueConstraint`をそのまま活かし、ビュー側で既存レコードを
  検出して`ModelForm`の`instance`に設定するアップサート方式を採用する（3.2参照）。
  フォーム側で一意性検証を無効化する方式は、Django 4.1以降`Model.full_clean()`の
  `validate_constraints`が`ModelForm._post_clean()`から`validate_unique=False`とは
  独立して働くため機能しない

### 3.2. ビューを実装する

`webapp/kakeibo/views.py` に以下を追加する。

- `_account_balance_context(balance_form=None)`: 画面6で共通の集計データ
  （総資産、口座種別内訳、口座一覧、資産推移、残高記録フォーム）をまとめる関数
- `AccountBalanceView`（`TemplateView`）: 3.1のコンテキストを描画する
- `BalanceRecordCreateView`（`FormView`）: `get_form_kwargs()`でPOSTされた
  `account`・`recorded_date`に一致する既存の`BalanceRecord`を検索し、あれば
  `instance`としてフォームへ渡す。`form_valid`は`form.save()`のみで、新規作成と
  上書きの両方に対応する

### 3.3. URLを実体に置き換える

`webapp/config/urls.py`の`account-balance`（05でHomeViewへ暫定割当、10で
DashboardViewへ暫定割当していたURL名）を`AccountBalanceView`へ置き換え、
残高記録入力用のURLを追加する。

```python
path("accounts-balance/", views.AccountBalanceView.as_view(), name="account-balance"),
path(
    "accounts-balance/record/",
    views.BalanceRecordCreateView.as_view(),
    name="balance-record-create",
),
```

### 3.4. テンプレートを作成する

`webapp/kakeibo/templates/kakeibo/account_balance.html`を新規作成する
（`base.html`を継承）。

- サマリー（総資産、口座種別ごとの内訳）
- 総資産推移グラフ（Chart.js、直近12ヶ月）
- 口座一覧（口座名・種別・最新残高・記録日）
- 残高記録入力フォーム

### 3.5. テストを追加する

`webapp/kakeibo/tests/test_account_balance.py`に以下を追加する。

- サマリーが総資産・口座種別内訳を正しく計算すること
- 無効化（`is_active=False`）した口座が集計・一覧から除外されること
- 残高記録の新規作成が行えること
- 同一口座・同一基準日への再登録が新規作成ではなく上書きになること

`webapp/kakeibo/tests/test_aggregation.py`にも、無効化口座の除外と
`assets_by_account_type`のテストを追加する。
