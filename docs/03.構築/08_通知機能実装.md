## 1. 概要

対応Issue: [#27](https://github.com/Seiya-Nakagawa/kakeibo/issues/27)

メール取込の解析失敗、バッチの異常終了、バックアップの失敗を管理者へ通知する機能を
Gmail API（`gmail.send`スコープ）で実装する。メール取込バッチ（Issue #24）・
バックアップ（Issue #28）から呼び出す共通基盤のため、先行して実装する。
対応する設計書: [基本設計書7.4節](../02.設計/基本設計書.md#74-運用保守要件-65)、
[6.1節](../02.設計/基本設計書.md#61-gmail-api)

### 3.2. Google Cloud Consoleで通知用OAuthクライアントを作成する

[基本設計書6.1.1節](../02.設計/基本設計書.md#611-認証情報の維持方式)のとおり、
ログイン認証（[03_認証機能実装.md](03_認証機能実装.md)）とは別のOAuthクライアントを
Gmail API用に作成する。

1. [Google Cloud Console](https://console.cloud.google.com/)で、ログイン認証と同一の
   プロジェクトを選択する
2. Gmail APIを有効化する
3. 「Google Auth Platform」→「データアクセス」でスコープ`gmail.send`（本Issueで使用）、
   `gmail.readonly`・`gmail.labels`（Issue #24で使用）を追加する
4. 「Google Auth Platform」→「クライアント」でOAuthクライアント（ウェブアプリケーション）を
   新規作成する
5. OAuth同意画面の公開ステータスを「本番公開」にする（[6.1.1節](../02.設計/基本設計書.md#611-認証情報の維持方式)
   のとおり、テスト状態特有のリフレッシュトークン7日失効を回避するため）
6. [OAuth 2.0 Playground](https://developers.google.com/oauthplayground/)等を用いて、
   4で作成したクライアントID・シークレットと対象スコープでリフレッシュトークンを取得する
   （通知メール送信元アカウントで認可する）

### 3.5. Gmail APIクライアントを実装する

`webapp/kakeibo/gmail_client.py`を新規作成する。メール取込バッチ（Issue #24）とも共有する。

```python
"""Gmail APIクライアント構築（基本設計書6.1節）。

ログイン認証（allauth、AUTHENTICATION_BACKENDS）とは別のOAuthクライアント
（GMAIL_API_*環境変数）を使用する。
"""

from django.conf import settings
from google.oauth2.credentials import Credentials
from googleapiclient.discovery import build

TOKEN_URI = "https://oauth2.googleapis.com/token"

SCOPE_READONLY = "https://www.googleapis.com/auth/gmail.readonly"
SCOPE_LABELS = "https://www.googleapis.com/auth/gmail.labels"
SCOPE_SEND = "https://www.googleapis.com/auth/gmail.send"


def build_gmail_service(scopes: list[str]):
    credentials = Credentials(
        token=None,
        refresh_token=settings.GMAIL_API_REFRESH_TOKEN,
        client_id=settings.GMAIL_API_CLIENT_ID,
        client_secret=settings.GMAIL_API_CLIENT_SECRET,
        token_uri=TOKEN_URI,
        scopes=scopes,
    )
    return build("gmail", "v1", credentials=credentials, cache_discovery=False)
```

### 3.6. 通知送信処理を実装する

`webapp/kakeibo/notifications.py`を新規作成する。

```python
"""エラー通知メール送信（要件6.5.1、基本設計書7.4節）。"""

import base64
import logging
from email.mime.text import MIMEText

from django.conf import settings

from kakeibo.gmail_client import SCOPE_SEND, build_gmail_service

logger = logging.getLogger(__name__)


def notify_admin(subject: str, body: str) -> bool:
    """管理者へエラー通知メールを送信する（メール取込の解析失敗、バッチの異常終了、バックアップの失敗）。

    通知自体の失敗でバッチ処理全体を止めないよう、例外は送出せずログ出力のみ行う
    （呼び出し元は戻り値のTrue/Falseで送信可否を判定できる）。
    """
    if not settings.NOTIFICATION_RECIPIENT_EMAIL:
        logger.warning("NOTIFICATION_RECIPIENT_EMAIL未設定のため通知メールを送信しません: %s", subject)
        return False

    message = MIMEText(body)
    message["to"] = settings.NOTIFICATION_RECIPIENT_EMAIL
    message["subject"] = subject
    raw = base64.urlsafe_b64encode(message.as_bytes()).decode()

    try:
        service = build_gmail_service([SCOPE_SEND])
        service.users().messages().send(userId="me", body={"raw": raw}).execute()
    except Exception:
        logger.exception("通知メールの送信に失敗しました: subject=%s", subject)
        return False
    return True
```

### 3.7. テストを追加する

`webapp/kakeibo/tests/test_notifications.py`に、`build_gmail_service`をモック化した
以下のテストを追加する。

- 正常系: Gmail APIの`messages().send()`が正しい引数（`userId="me"`、`body.raw`）で
  呼ばれること
- Gmail API呼び出しが例外を送出した場合、例外を再送出せず`False`を返すこと
- `NOTIFICATION_RECIPIENT_EMAIL`未設定の場合、APIを呼ばず`False`を返すこと
